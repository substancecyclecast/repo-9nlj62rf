# Соглашение об обработке персональных данных (DPA) — SnabAgent

**Версия 1.0 от 01.01.2026**

> Шаблон, соответствует требованиям Федерального закона № 152-ФЗ «О персональных данных». Требуется юридическая проверка перед использованием.

## 1. Стороны и роли

- **Оператор (Лицензиат)** — юридическое лицо, использующее ПО SnabAgent.
- **Обработчик (Лицензиар)** — ООО «СнабАгент», предоставляющее ПО как сервис.

В рамках сервиса Лицензиар обрабатывает персональные данные по поручению Оператора в соответствии с ч. 3 ст. 6 152-ФЗ.

## 2. Категории субъектов и данных

### 2.1. Субъекты

- Сотрудники Оператора (закупщики, менеджеры).
- Контактные лица контрагентов (поставщики, заказчики).
- Авторы заявок и КП.

### 2.2. Категории данных

| Категория | Примеры | Чувствительность |
|---|---|---|
| Идентифицирующие | ФИО, должность | средняя |
| Контактные | email, телефон | средняя |
| Юридические лица | ИНН, КПП, ОГРН | низкая (юр. данные) |
| Аутентификационные | хеш пароля (bcrypt), JWT-токен | **высокая** |
| Финансовые | цены КП, условия оплаты | средняя |

### 2.3. Запрещено к обработке

ПО SnabAgent **не предназначено** для обработки:
- паспортных данных, СНИЛС, ИНН физических лиц;
- медицинских данных, биометрии;
- сведений об особых категориях персональных данных (расовая принадлежность, политические взгляды, состояние здоровья и т.д.).

Если Оператор загружает такие данные, ответственность за нарушение 152-ФЗ несёт Оператор.

## 3. Цели обработки

3.1. Обработка осуществляется исключительно в целях выполнения функций ПО:
- регистрация и аутентификация пользователей;
- автоматизация закупочного процесса (Planner→Reporter);
- ведение audit-log для соответствия 152-ФЗ и 44-ФЗ/223-ФЗ;
- предоставление отчётов и аналитики Оператору.

3.2. **Запрещено** использование данных для:
- маркетинга от лица Лицензиара;
- передачи третьим лицам без согласия Оператора;
- обучения внешних LLM-моделей (используются изолированные инстансы);
- иных целей, не связанных с выполнением функций ПО.

## 4. Технические меры защиты

| Мера | Реализация |
|---|---|
| Шифрование при передаче | TLS 1.3 для всего HTTP/WS трафика |
| Шифрование при хранении | AES-256 для БД (Yandex Cloud / on-prem) |
| Маскинг PII в audit-log | Telephone → `+7916***4567`, ФИО → `И***ов И.И.` |
| Ограничение доступа | JWT + RBAC (admin/buyer/viewer), per-customer isolation |
| Хеширование паролей | bcrypt с 12 раундами + 72-byte truncation |
| Audit-log | append-only, retention 5 лет |
| Резервное копирование | ежедневное, 30-дневное хранение |
| Сегментация сетей | API/UI/БД в отдельных VPC, доступ только через bastion |

## 5. Местонахождение данных

5.1. Все данные хранятся **на территории Российской Федерации**:
- Yandex Cloud (Москва / Калуга) — для SaaS-клиентов;
- On-prem ЦОД Оператора — для Enterprise-клиентов.

5.2. LLM-запросы (Planner, Verifier и др.) направляются только в:
- YandexGPT (primary);
- GigaChat (fallback);
- собственные Llama-3 инстансы в РФ ЦОД.

5.3. **Запрещено** использование облачных LLM-провайдеров вне РФ (OpenAI, Anthropic и т.д.) для production-окружения. Они доступны только для тестов и разработки.

## 6. Срок хранения

| Тип данных | Срок |
|---|---|
| Пользователи (User) | до удаления учётной записи + 90 дней |
| Лоты (Lot) | 3 года |
| КП поставщиков (Bid) | 3 года |
| Audit-log | 5 лет (несбрасываемый) |
| Резервные копии | 30 дней |

По истечении срока данные удаляются автоматически.

## 7. Передача данных третьим лицам

7.1. Передача данных третьим лицам **запрещена**, за исключением:
- LLM-провайдеры в РФ (YandexGPT, GigaChat) — для выполнения функций ПО;
- СПАРК-Интерфакс, Контур.Фокус — при явном включении интеграции Оператором;
- государственные органы — по их обоснованному запросу с уведомлением Оператора.

7.2. Перед передачей данных в LLM:
- из текста удаляются все PII (ФИО, телефоны, email) через маскинг;
- передаётся только обезличенная техническая информация (артикулы, ГОСТ, объёмы).

## 8. Права субъектов

8.1. Субъекты данных вправе обращаться к Оператору с запросами на:
- предоставление информации об обработке их данных;
- уточнение, изменение, удаление данных;
- отзыв согласия на обработку.

8.2. Оператор обрабатывает запрос в течение **30 календарных дней**.

## 9. Уведомление об инцидентах

9.1. При обнаружении инцидента безопасности, затрагивающего данные Оператора:
- Лицензиар уведомляет Оператора в течение **24 часов**;
- предоставляет детальный отчёт в течение **72 часов**;
- принимает меры по устранению инцидента.

9.2. Оператор уведомляет Роскомнадзор согласно ч. 3.1 ст. 21 152-ФЗ при необходимости.

## 10. Аудит

10.1. Оператор вправе проводить аудит соответствия требованиям 152-ФЗ:
- 1 раз в год — стандартный;
- внеочередной — при инциденте безопасности.

10.2. Лицензиар обязан:
- предоставить документацию по защите данных;
- допустить аудитора Оператора (по предварительному согласованию);
- устранить выявленные несоответствия в течение 60 дней.

## 11. Заключительные положения

11.1. Настоящее DPA является неотъемлемой частью EULA.

11.2. Применяется законодательство Российской Федерации, в первую очередь:
- Федеральный закон № 152-ФЗ «О персональных данных»;
- Постановление Правительства РФ № 1119;
- Приказ ФСТЭК России № 21;
- Приказ ФСБ России № 378.
